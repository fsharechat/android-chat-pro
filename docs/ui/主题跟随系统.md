# Android主题跟随系统回归

## 问题与原因

系统浅色时，手动选深色并重开页面，再选跟随系统，页面仍为深色；系统深色时反向操作也会保留浅色。

项目使用androidx.appcompat:appcompat:1.0.0-beta01。该版本的AppCompatDelegateImpl.applyDayNight遇到MODE_NIGHT_FOLLOW_SYSTEM直接跳过资源更新。手动模式曾通过updateConfiguration覆盖页面资源，而主题设置的“重启”只清空任务并启动SplashActivity，并未退出进程，因此新页面可能继续使用缓存的手动主题。偏好中已经正确保存“跟随系统”，问题不是保存失败。

## 修复

ThemeManager保留三种用户选择；跟随系统时，读取Resources.getSystem的当前夜间配置，明确向旧版AppCompat传入MODE_NIGHT_YES或MODE_NIGHT_NO。不能读取当前Activity的配置，因为它可能仍含手动覆盖值。

MyApp在onConfigurationChanged中通知ThemeManager。只有用户选择跟随系统时才同步系统夜间配置；手动浅色、深色不受系统切换影响。isDarkMode也从系统配置解析跟随系统的实际结果。

## 回归

测试入口为ThemeInstrumentation；测试会修改系统夜间模式，finally恢复启动参数对应的系统模式及原应用主题偏好。使用专用测试设备，systemDark参数应与测试启动时的系统实际状态一致。

```sh
JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-11.0.17.jdk/Contents/Home \
  ./gradlew -I scripts/theme-tests.init.gradle :chat:assembleDebug :chat:assembleDebugAndroidTest --offline
# 先覆盖安装本次生成的debug APK及chat-debug-androidTest.apk。
adb shell cmd uimode night no
adb shell am instrument -w -e systemDark false cn.comsince.fschat.test/cn.wildfire.chat.app.ThemeInstrumentation
adb shell cmd uimode night yes
adb shell am instrument -w -e systemDark true cn.comsince.fschat.test/cn.wildfire.chat.app.ThemeInstrumentation
```
